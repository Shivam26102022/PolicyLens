# Data Model: Session Chat and Memory

## Workspace

| Field | Type | Constraints |
|---|---|---|
| `workspace_id` | UUID | Opaque browser-profile identifier; required on workspace-scoped API calls |
| `data_use_acknowledged` | boolean | Defaults to `false`; must be explicitly set before creating persistent sessions or turns |
| `data_use_acknowledged_at` | UTC timestamp or null | Set when the user confirms that only public, synthetic, or appropriately anonymized content will be stored |
| `long_memory_enabled` | boolean | Defaults to `false` for a new workspace; enabling requires data-use acknowledgement |
| `created_at` | UTC timestamp | Assigned by the backend |
| `updated_at` | UTC timestamp | Updated when preferences change |

The identifier is an isolation key for this local, single-operator application, not an authentication credential. The UI must explain that restricted or identifiable private content must not be stored.

## Conversation Session

| Field | Type | Constraints |
|---|---|---|
| `session_id` | UUID | Backend-generated primary key |
| `workspace_id` | UUID | Required owner scope |
| `title` | string | Derived from the first user message, trimmed to at most 80 characters; otherwise `New conversation` |
| `created_at` | UTC timestamp | Assigned by the backend |
| `updated_at` | UTC timestamp | Updated after every stored turn |

A session belongs to exactly one workspace. All reads and mutations include both `session_id` and `workspace_id`; a missing or foreign session returns the same not-found response.

## Conversation Turn

| Field | Type | Constraints |
|---|---|---|
| `turn_id` | UUID | Backend-generated primary key; also the stable long-memory record ID |
| `session_id` | UUID | Required parent session |
| `position` | integer | Monotonic within a session; unique with `session_id` |
| `user_content` | string | 1-4000 characters |
| `assistant_content` | string or null | At most 12000 characters; null until a response is saved |
| `answer_json` | JSON object or null | Validated `AgentAnswerResponse` for restoring the saved answer |
| `status` | enum | `in_progress`, `completed`, or `failed`; transitions from `in_progress` to one terminal state |
| `created_at` | UTC timestamp | Assigned when the request is accepted |
| `completed_at` | UTC timestamp or null | Set for terminal state |

Only completed turns with a non-empty assistant response are eligible for hot context. A failed or still-running turn is visible in warm history but does not count as a completed pair.

## Hot Context

Not stored as a separate entity. It is selected from the five most recent `completed` turns in the active session, ordered oldest-to-newest for model input. The resulting context is no more than ten messages and remains subject to the existing total-character limit.

## Warm Session History

The complete ordered set of `ConversationTurn` records. The API returns a bounded page of at most 100 turns and an opaque next cursor; older pages remain available until the session is deleted. Warm history is not automatically sent to a model.

## Long-Term Memory

Stored only in the dedicated Chroma collection under a stable memory-specific persistence path below the configured Chroma root; the source transcript remains authoritative in SQLite. The memory path is separate from the per-build corpus database paths.

| Field | Type | Constraints |
|---|---|---|
| `id` | string | Same UUID as the source `turn_id`; unique within the memory collection |
| `workspace_id` | string metadata | Required exact-match filter for every query and delete |
| `session_id` | string metadata | Required for session-scoped deletion |
| `created_at` | string metadata | UTC timestamp |
| `content` | document text | Bounded combination of the user message and assistant response, at most 4000 characters; treated as untrusted context |
| `embedding` | float vector | Generated by the configured embedding provider and matching the collection's versioned embedding identity |
| `embedding_provider` | string metadata | Provider name used for the stored vector |
| `embedding_model_id` | string metadata | Model identifier used for the stored vector |
| `embedding_dimension` | integer metadata | Vector dimension used for the stored vector |

One record is stored per eligible completed turn after acknowledgement and explicit memory enablement. The per-request result is limited to five records. Disabling long-term memory preserves existing vectors for later re-enabling, while clearing memory deletes all records in the workspace. If the configured embedding identity changes, retrieval reports `embedding_mismatch` and writes fail closed until the workspace explicitly clears it; when safe, the incompatible collection is removed and a replacement is created lazily on the next consented memory-enabled write. No automatic re-embedding occurs.

## Relationships and Deletion

- Workspace 1-to-many Sessions.
- Session 1-to-many Conversation Turns.
- A completed turn has zero or one derived Long-Term Memory record.
- Deleting a session removes its memory records first and then deletes the session and turns transactionally. If vector deletion fails, transcript deletion is not reported as successful.
- Clearing workspace memory removes all Long-Term Memory records but leaves sessions and warm history intact.
