## Improving quality from evidence

Latest registered run `ad3163da-7b37-440d-b317-83b1f0075d97` used `agent-v4` and the non-agent baseline (`gpt-6-luna`, seed 0, 67 cases). All-attempt expected-behaviour accuracy is 0.866 for the agent and 0.433 for the baseline (paired difference +0.433, 95% bootstrap [+0.299, +0.567], discordant 31/2, exact McNemar p<0.0001); failed generations count as incorrect. The previous `agent-v3` run (`18454f3c`) scored 0.881 against 0.418; the two agent scores are statistically indistinguishable. AI-judged groundedness is 3.54/5 and relevance 4.58/5 (scored by the generating model, so use them as a screen, not a verdict). Dev/test accuracy is 0.853/0.879 for the agent, so the earlier dev-over-test gap is not present in `agent-v4`. Lowest categories: adversarial citation (0.333) and the single-case conflict and local-model-failure categories (0.000), then invalid MCP arguments, multi-source synthesis, multi-step tool use, unauthorized source and user injection (0.667 each); categories of three or fewer cases are descriptive. All 67 case definitions are human-approved under `reviewer-user`. A 19-answer human review of the deployed app is recorded in `data/manifests/evaluation-review-manifest.json` (rubric: `docs/evaluation/evaluation-review-rubric.md`). Retrieval results on 40 anchored cases have overlapping intervals; they do not establish that one mode is superior.

Prioritize evidence that can distinguish a code fix from a model/provider change:

1. Review a stratified sample of the `ad3163da` answers independently for grounding, relevance, citation correctness, and safety, and keep this distinct from case-definition review (a blind packet is generated by `scripts/blind_review.py`). Re-run with a judge that is not the generator.
2. Convert the recorded calculation, citation, synthesis, injection, and refusal failures into focused regression tests. The host now renders calculation rows as readable summaries, but this formatting fix is not a new quality result and does not compute cross-query differences.
3. Keep re-ranking and metadata changes as controlled experiments. A bounded local cross-encoder is now implemented and measured on the small Feature 003 engineering set: mean Recall@6 changed from 0.571 to 0.619 and nDCG@6 from 0.530 to 0.578 across three chunkers, while mean latency rose from 7.07 ms to 219.46 ms. The result is mixed by chunker and has no uncertainty intervals; it is not evidence of a general quality win. Keep it configurable, preserve the hybrid fallback, and require a larger independently reviewed set with latency/uncertainty analysis before making a broad superiority claim.

## Detecting change

The following are proposed controls, not currently deployed monitoring:

- **Data:** hash-pinned source snapshots; a scheduled job re-fetches sources and flags changed hashes, new years and schema changes before the index is rebuilt.
- **Model and embeddings:** pin model and embedding identity per run; run a fixed canary set nightly and on any provider version change; alert on drops in Recall@k, citation validity or abstention rate.
- **User behaviour:** track topic mix, out-of-corpus query rate, abstain/clarify rates and feedback. Rising out-of-scope queries indicate corpus gaps.

## Confidence, explainability, provenance, review

Every claim carries verified excerpts and a source, passage and hash, so provenance is checkable. Deterministic numbers show formula, rounding and rows. The UI keeps source facts, calculations and model wording distinct, and shows uncertainty and conflicts. Add per-claim feedback (supported / not supported), a reviewer queue for low-confidence or conflicting answers, and independent double review with agreement statistics on a rolling sample.

## Privacy, access, audit, injection, third-party risk

- Private deployment inside the government tenant, with an in-region model endpoint under a zero-retention agreement, or a self-hosted model for sensitive tiers.
- SSO and role-based access; retrieval filters passages by the caller's entitlements before the model sees them (permission-aware retrieval); workspaces isolate memory.
- Append-only audit log of query hash, sources used, model and prompt version, tool calls and outcome, without raw content by default; retention and deletion policies.
- Injection defence in depth: untrusted-content labelling, single read-only allow-listed tools, argument validation, passage hash verification, output citation checks, a provider safety filter and red-team regression cases in CI.
- Third-party model risk: pinned versions, contractual data terms, a documented exit path to a local model, and a routing policy with no silent fallback across trust levels.

## Latency and cost

Local embeddings; retrieval limited to the top-k passages; effort `none` and bounded output tokens; batch geographies into one tool call; cache retrieval and statistics by index version and arguments; use a small model for routine lookups and escalate only for synthesis; track token cost per case type and set per-workspace budgets.

## First two priorities and how to measure them

1. **Verify the measured prompt with independent review.** `agent-v4` is measured live (run `ad3163da`); the blind second review of its answers is the next evidence step. Report all-attempt expected behavior separately from human-rated grounding, relevance, citation correctness, and safety. Do not tune against `test` further.
2. **Close measured safety and usability failures.** Add offline regressions for calculation summaries, citation provenance, conflict/synthesis, prompt injection, and out-of-scope/unauthorized requests. Measure these categories in a later authorized run; do not infer gains from unit tests or target scores from one-case strata.
